# RadarX Backend

RadarX backend is the 24/7 market-analysis service for the Android/Web client.

## What it does
- Maintains Binance public WebSocket streams for market/ticker/deep data.
- Scans a liquidity-filtered USDT universe every few seconds.
- Deep-scores candidates using volume, momentum, volatility compression, VWAP, order-book imbalance, tape flow, multi-timeframe alignment and relative strength.
- Produces PRE-BREAKOUT / BREAKOUT / BUILDING / NORMAL / EXHAUSTED-HIGH-RISK phases.
- Calculates conditional Entry, SL and TP1/TP2/TP3 with risk/reward.
- Keeps sensitive Binance credentials on the server only.
- Exposes protected account/order endpoints behind a separate RADARX_CONTROL_TOKEN.

## Safety defaults
The server is paper-only by default:
- RADARX_ALLOW_LIVE_TRADING=false
- RADARX_AUTO_EXECUTION=false
- RADARX_ALLOW_FUTURES=false

The intended Binance API key is Read + Spot trading only, with withdrawals, margin, futures and portfolio-margin permissions disabled.
The backend rejects live execution unless the API restriction check passes and the RadarX control token is valid.

## Run
```bash
cp .env.example .env
docker compose up -d --build
curl http://127.0.0.1:8000/api/v1/health
curl http://127.0.0.1:8000/api/v1/scan?force=true
```

For a full production deployment, see DEPLOY_VPS.md.

## Protected execution API
Use Authorization: Bearer <RADARX_CONTROL_TOKEN>.

POST /api/v1/execution/plan

Request:
```json
{"symbol":"BTCUSDT","balance_usdt":1000}
```

POST /api/v1/execution/limit-buy

The backend does not accept a client-supplied price/quantity for live execution.
It uses the most recent signal generated by the scanner, runs the risk engine, reads Binance exchangeInfo rules, normalizes price/quantity to the symbol filters, and only then submits a Spot LIMIT BUY when all safety switches are enabled.
